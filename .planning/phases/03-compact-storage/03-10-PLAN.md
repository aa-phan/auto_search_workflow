<objective>
Close UAT gap G-3-7 (review finding WR-10). The owner asked for this fix before the WR-01..WR-09 review fixes are deployed. An Identity entry with no posting ID (a bare kind letter such as `b`) must hold no key. It must still be flagged `identity_entry`, and deleting it, its only repair, must not be a counted `identity_shrunk`.

Purpose: today `IdentitySet._reindex` stores the empty posting ID that `decode_entry("b") == ("b", "")` returns, as the key `stem|`. `distinct_count()` counts that key, and no posting can ever match it (`stem_and_id` returns None for an empty ID). Deleting the entry therefore lowers the figure below the high-water mark for good (WR-06). Every later run is degraded, and the WR-05 gate holds the fold back while `Events` grows. STOR-01 needs the compact store to keep folding, so a false permanent alarm here works against the phase goal. Before writing this plan, a scratch prototype on the Sheets fake (mocked) showed the bug: the mark went from 15 to 16, then deleting the bare entry caused `identity_shrunk` and `storage fold skipped`. With the one-line fix the mark stayed at 15, the next-day fold ran and `--storage-parity` exited 0.

Output: the `_reindex` fix and the mirrored rule in `storage_report.logical_counts`, plus offline tests: one end to end on the Sheets fake, one pure, and one for the storage report. The pinned count changes from (3, 3) to (2, 2). SPEC, D-57 and STATUS are updated in the same change (AGENTS rule 1). Every check is mocked. Nothing is pushed, deployed or dispatched.
</objective>
